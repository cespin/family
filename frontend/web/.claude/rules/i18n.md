# Internationalization — frontend/web

The app uses i18next and react-i18next. `es-VE` is the default catalog and the fallback for every other language.

## No user-visible literals in components

Everything a person can read or hear comes from a catalog. That includes text in JSX, `title`, `alt`, `placeholder` and `aria-label` attributes, props that render as copy, and text held in constants.

```jsx
// WRONG
<Button onClick={signOut}>Cerrar sesión</Button>

// CORRECT
const { t } = useTranslation();
<Button onClick={signOut}>{t('common:actions.signOut')}</Button>
```

## Always use full keys

Always call `t('namespace:key')`, with the namespace and a single-quoted literal. `src/i18n/i18n.test.js` scans the source for exactly that form and checks each key against the `es-VE` catalog.

```jsx
t('dashboard:empty.title')            // CORRECT
t('empty.title')                      // WRONG: no namespace, so the test reports it as unknown
t("dashboard:empty.title")            // WRONG: the scan does not see double quotes
t(`dashboard:${section}.title`)       // WRONG: the scan does not see computed keys
```

To choose between messages, write each full key out:

```jsx
firstName ? t('dashboard:greeting', { name: firstName }) : t('dashboard:greetingFallback')
```

The scan compares the literal key with the keys in the catalog, so a plural key that exists only with suffixes such as `_one` and `_other` fails it. Extend the test before introducing plurals.

## One namespace per dashboard module

Each dashboard module gets its own file under `src/i18n/locales/<locale>/`, and the filename is the namespace. `dashboard.json` is the namespace `dashboard`. Text shared across modules goes in `common.json`, and sign-in text goes in `auth.json`.

Catalog files are discovered automatically, so a new namespace needs no registration.

## Formatting goes through `src/i18n/format.js`

Format numbers, money and dates only with `formatNumber`, `formatCurrency`, `formatDate` and `formatRelativeTime`. They follow the active language. Don't call `Intl.*`, `toLocaleString` or `toLocaleDateString` anywhere else, and don't build a currency symbol by hand.

The formatters turn a missing value into a real-looking one, so check for absence first. See "Absent is not zero" in `patterns.md`.

## API errors go through `src/i18n/errors.js`

Show an API failure with `errorMessage(error.code)`. It translates the backend's stable `code` and falls back to `common:errors.generic` for an unknown one. It is the one place that computes a key.

Never display the `message` field of an API error. It is English diagnostic text.

A new backend error code needs a translation under `errors` in `common.json`, and `src/i18n/i18n.test.js` fails without it.

## es-VE tone

- Address the reader informally as "tú": "Entra con tu cuenta", never "usted" or "vos".
- Use neutral Venezuelan Spanish that any family member understands, without slang.
- Keep it warm and brief, in sentence case.

## Adding a language

Adding a language means adding a catalog folder under `src/i18n/locales/<locale>/` and nothing else. `src/i18n/index.js` discovers it and matches it to the browser's preferences. The folder must contain the same files and keys as `es-VE`, which `src/i18n/i18n.test.js` enforces.
